\subsection*{Architecture interpretation}
The comparison positions ToolPlane around explicit tool resources, desired state, revision identity, and runtime governance rather than API conversion alone. This is a design-positioning argument derived from the archived matrix, not a measured superiority claim.

A resource can bind an input contract, HTTP mapping, and credential reference. An admission record does not, by itself, prove an independent reviewer or prior human approval. A stored desired-state model does not, by itself, prove measured recovery time. A version selector does not, by itself, prove that policy and execution share one immutable per-call revision.

\subsection*{Source and version caution}
The prototype rows describe an evaluated profile. They must not be read as current-source certification or general guarantees across all ToolPlane deployments. The historical advanced behavior is not tied to every retained run by an observed immutable binary identifier.
