# ERPBridge v0.6.0-alpha.2

This alpha release improves native Windows `bridgectl` support and bundles the
`bridgectl-ops` 3.5.0 guidance. Existing Linux runtime behavior, configuration
paths, context naming, permissions, release targets, and deployment settings
remain unchanged.

## Windows CLI improvements

- Reject saved context names that differ only by case, such as `prod` and
  `Prod`, before registry access, context-selection writes, or management MCP
  child execution on Windows.
- Reject reserved Windows device stems such as `CON`, `NUL.test`, `COM1`, and
  `LPT9` before constructing registry paths. Refusal preserves existing files;
  there is no automatic migration or merging.
- Add native Windows x64 CI for configuration and registry files, command exit
  codes/streams, skill installation, MCP framing/pinning/cancellation, and
  PowerShell CLI/Console smoke checks.
- Document non-admin ZIP installation, SHA256 checks, UTF-8 configuration,
  PowerShell completion, manifest files, Windows MCP client paths, and manual
  recovery for unsafe context names.

## Bundled operations guidance

The embedded `bridgectl-ops` skill is version 3.5.0. It covers management MCP
discovery, serial operations, result checks, independent write readback,
action-specific preflight, and bounded operational-memory retrieval. It retains
exact-action approval and redaction requirements. Install this release's bundled
guidance with `bridgectl skill install`; review existing installed content before
using `--force`.

## Validation and limits

Native Windows x64 tests and PowerShell smoke checks passed in GitHub Actions
on Windows NT 10.0.26100.0 with PowerShell 7.6.6. Linux focused tests, the full Go
test suite, frontend/Console checks, and Windows amd64/arm64 cross-builds passed.
The local Linux CLI/config/registry results match the pre-change binary baseline.

This is still an alpha release. These checks are **not** claimed:

- Default-browser launch and interactive Ctrl+C cleanup on Windows
- Installation/configuration walkthrough under a clean non-admin Windows user
- Native execution of the PowerShell 5.1 documentation examples
- Windows ARM64 runtime validation; ARM64 binaries are cross-built only

Windows file access is governed by inherited directory ACLs. Unix mode `0600`
does not establish an owner-only Windows ACL, and config replacement is not
claimed to be crash-atomic on Windows.

## Downloads

Choose `bridgectl_Windows_x86_64.zip` for Windows x64 or
`bridgectl_Windows_arm64.zip` for Windows ARM64. Verify the exact archive entry
in `checksums.txt` before extraction. Matching checksums detect corruption, not
independent publisher authenticity. Linux/macOS CLI archives and Linux server
archives remain available. Archive SBOMs and the signed checksum metadata are
published by the existing release pipeline.

The management MCP server and runtime server remain separate. `bridgectl mcp
--stdio` manages ERPBridge; `erpbridge-server --stdio` serves published ERP tools.
Server release targets remain Linux amd64 and arm64.
